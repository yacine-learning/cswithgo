What this project practises
  • A stack to follow nesting (1.2.3): what is open, and in which order it must close.
  • A map to add up by name (1.2.2), and a slice sorted to rank the results (1.2.1).
  • Errors that say where: a line number and what was expected.

The situation

A profiler records, while a program runs, when each function is entered and when it returns. Calls nest, because the call stack (1.3.1) is a stack: lex is called inside parse, which is called inside main, and the last function entered is the first to return. From such a trace you can tell where the time goes, and you can tell when a trace is corrupt: a return that does not match the innermost open call.

Profiling is old: gprof, from Berkeley in 1982, already drew the call graph of a program with the time spent in each function. Go ships its own, pprof.

10 start main
12 start parse
15 start lex
41 end lex
44 end parse
45 start eval
60 end eval
61 end main

Here main took 51, lex 26, eval 15, parse 32 (it includes the call to lex), and the deepest nesting is 3.
