History

In 1951 David Huffman's information theory class at MIT was given a choice by the professor, Robert Fano: take the final exam, or write a term paper on finding the most efficient binary code. Huffman chose the paper, could not prove any method optimal, and was about to give up and study for the exam when he found the idea: build the code tree from the bottom up. It beat the method Fano himself had worked on with Claude Shannon. He published it in 1952.

The problem it fixes

Fixed-size codes (8 bits per character) waste space when some symbols are far more common than others: in English text, e appears far more often than z.

How it works

Give short codes to frequent symbols and long codes to rare ones, with no code a prefix of another so the bits can be decoded without separators. To build the tree: put every symbol in a priority queue (D10) by frequency; repeatedly take the two least frequent, join them under a new node whose frequency is their sum, and put it back. The last node is the root; left is 0, right is 1. No code built symbol by symbol is shorter on average.

Where it is used

  • DEFLATE, the compression inside gzip, zip and PNG, uses Huffman codes (Go: compress/flate).
  • JPEG images and MP3 audio use Huffman coding as their last step.
  • Fax machines used fixed Huffman-style codes for runs of black and white.

No exercise: building the tree is a heap exercise you already did (D10), and the bit-level encoding is mostly plumbing. Keep the idea: frequent symbols get short codes, built bottom-up from the two rarest.
