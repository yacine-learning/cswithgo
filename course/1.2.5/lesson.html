Keep this
  • A linked list is nodes scattered in memory, each pointing to the next: inserting or removing at a node you hold is O(1), but reaching the i-th node is O(n).
  • In practice a slice usually wins, because memory is read in cache lines and a slice's elements are side by side. A list wins when you keep pointers to nodes and move them around: an LRU cache is the classic case.
  • A dummy (sentinel) head node removes the special case for the first element.

The problem

In the 1950s, programs had to declare how much memory each structure would use, in advance. A program that builds structures as it thinks, of sizes nobody can predict, needs memory that grows piece by piece, and pieces that can be inserted between others without moving anything.

Where it comes from

Allen Newell, Cliff Shaw and Herbert Simon, at RAND and Carnegie Tech, invented linked lists in 1955–56 for their Information Processing Language (IPL), to write the Logic Theorist, often called the first artificial intelligence program, which proved theorems from Russell and Whitehead's Principia Mathematica. The box-and-arrow drawing of a list first appears in Newell and Shaw's 1957 paper. IPL inspired Lisp, and Newell and Simon received the 1975 Turing Award, partly for list processing.

The idea

Each node holds a value and the address of the next node. To insert after a node, make the new node point where it pointed, then point it at the new node: two assignments, whatever the length. To find a value, though, you must walk from the head.

Why slices are usually faster anyway

A CPU reads memory in blocks of 64 bytes (cache lines) and guesses what comes next. A slice of ints puts 8 of them in each block, in order. A list's nodes can be anywhere, so each step may wait for a trip to main memory, a hundred times slower than the cache. Inserting into the middle of a slice moves elements, but moving a few thousand contiguous ints is often faster than one walk to the middle of a list. Measure before choosing a list for speed.

Lists still matter where nodes are held and moved: the Linux kernel keeps processes in doubly linked lists, Go's container/list backs LRU caches, and a free list recycles memory blocks.
