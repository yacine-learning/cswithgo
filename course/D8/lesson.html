History

In 1962 two Soviet mathematicians, Georgy Adelson-Velsky and Evgenii Landis, published the first tree that rebalances itself: the AVL tree. In 1972 Rudolf Bayer invented the "symmetric binary B-tree". In 1978 Leonidas Guibas and Robert Sedgewick reformulated it with a colour bit on each node: the red-black tree. Why red? By Sedgewick's account, it was the best-looking colour their laser printer at Xerox PARC could print.

The problem it fixes

A plain binary search tree (D7) fed sorted keys becomes a list: every operation O(n). Real data often arrives sorted (timestamps, increasing IDs).

How it works

After each insert or delete, repair the shape with rotations: local moves of three nodes that keep the keys in order but shorten one side. AVL keeps the heights of the two subtrees of every node within 1 of each other. Red-black keeps a looser rule (no red node has a red child, every path has the same number of black nodes), so the longest path is at most twice the shortest: height ≤ 2 log₂ n, and fewer rotations per update. Both guarantee O(log n) for every operation.

Where it is used

  • The Linux kernel uses red-black trees in many places, including its process scheduler.
  • Java's TreeMap and, in practice, C++'s std::map are red-black trees.
  • Go's standard library has none: when Go code needs order it usually sorts a slice, or uses a B-tree package (D9).

No exercise: the rotation cases are long to write and quick to forget. What is worth keeping is the guarantee (O(log n), whatever the order of the input) and the fact that balancing exists. You will use these trees through libraries, not write them.
