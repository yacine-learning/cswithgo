What this project practises
  • A graph and its reverse (1.4.1), with an in-degree count per node.
  • Topological sorting: an order where every edge goes forward. Done level by level, it is a BFS (1.4.2) over the nodes whose dependencies are all done.
  • Detecting the impossible case (a cycle) instead of producing a wrong answer.

The situation

A release touches a dozen services. Each must be deployed after the services it depends on, and you want it fast: deploy in parallel everything that can go together. Terraform, Helm (with dependencies), Bazel, Make and systemd all solve this same problem before running anything.

The method is Arthur Kahn's, published in 1962 to order the tasks of large PERT project-management networks: repeatedly take every task with no unfinished prerequisite. Unix has a small command for it, tsort.

web    -> api
api    -> db, cache, queue
worker -> db, queue

wave 0: cache db queue
wave 1: api worker
wave 2: web
