What this project practises
  • A graph and its reverse (1.4.1), with an in-degree count per node.
  • Topological sorting: an order where every edge goes forward. Done level by level, it is a BFS (1.4.2) over the nodes whose prerequisites are all done.
  • Detecting the impossible case (a cycle) instead of producing a wrong answer.

The situation

Mathematics is learned in an order: calculus needs functions, functions need algebra, statistics needs probability and calculus. Given the prerequisites of each topic, which topics can be studied in the first semester, which in the second, and so on, each as early as possible? The same question orders the steps of any computation where some results are needed before others: a compiler orders the pieces of a program, a spreadsheet the cells of a sheet.

The method is Arthur Kahn's, published in 1962 to order the tasks of large PERT networks, then used to plan big engineering projects: repeatedly take everything with no unfinished prerequisite. Unix has a small command for it, tsort.

calculus    needs functions, algebra
functions   needs algebra
probability needs algebra, combinatorics
statistics  needs probability, calculus

semester 0: algebra combinatorics
semester 1: functions probability
semester 2: calculus
semester 3: statistics
