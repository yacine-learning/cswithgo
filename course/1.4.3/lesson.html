What this project practises
  • A graph of imports and its reverse (1.4.1), with an in-degree count per node.
  • Topological sorting: an order where every edge goes forward. Done level by level, it is a BFS (1.4.2) over the nodes whose prerequisites are all done.
  • Detecting the impossible case (a cycle) instead of producing a wrong answer.

The situation

A program is made of packages, and a package can only be compiled once everything it imports is compiled. Given what each package imports, which packages can be compiled first, which in the second round, and so on, each as early as possible? Everything in one round is independent, so a compiler with several processors can build a whole round at once. The same question orders any computation where some results are needed before others: the cells of a spreadsheet, the instructions a processor may run out of order.

The method is Arthur Kahn's, published in 1962 to order the tasks of large PERT networks: repeatedly take everything with no unfinished prerequisite. In April 1976 at Bell Labs Stuart Feldman wrote make, which rebuilds a program from a graph of files and what each depends on, after a colleague lost a morning debugging a program that had simply not been recompiled. Unix also has a small command for the ordering alone, tsort.

main    imports parser, eval
parser  imports lexer, ast
eval    imports ast, strconv
lexer   imports token, unicode
ast     imports token

round 0: strconv token unicode
round 1: ast lexer
round 2: eval parser
round 3: main
