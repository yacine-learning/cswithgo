Keep this
  • In a binary search tree, every node has smaller keys on its left and larger keys on its right. A search follows one path from the root: O(height).
  • Balanced, the height is about log₂ n: a million keys in about 20 steps. Inserted in sorted order, the tree is a straight line: O(n). Real systems use self-balancing trees (red-black, AVL) or, on disk, B-trees.
  • Unlike a hash map, a tree keeps its keys in order: smallest, largest, "the largest key ≤ x", all keys in a range.

The problem

A hash map finds an exact key in O(1), but knows nothing about order: "which is the next eclipse after today?", "which geological period was the Earth in 300 million years ago?", "all words between a and f". A sorted array answers those with binary search, but inserting into the middle of an array moves everything after it. You want sorted order and cheap insertion together.

Where it comes from

The binary search tree was discovered independently around 1960 by several people: P. F. Windley, A. D. Booth and A. J. T. Colin, and T. N. Hibbard. Two years later, in 1962, the Soviet mathematicians Georgy Adelson-Velsky and Evgenii Landis published the AVL tree, the first one that rebalances itself after each insertion to keep its height near log₂ n.

The idea

Compare with the root: smaller goes left, larger goes right, and the same question repeats in the subtree, which is a smaller tree: recursion (1.3.1). It is binary search (1.5.1) laid out as pointers, so inserting is just hanging a new leaf where the search ended.

Trees that stay balanced

Self-balancing trees rotate nodes after inserts and deletes so the height stays O(log n) whatever the order of the keys. A B-tree goes further: each node holds hundreds of keys, so the tree is very wide and very shallow, which suits storage read in large blocks: a lookup among millions of keys reads only 3 or 4 nodes.
