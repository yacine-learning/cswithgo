History

Burton Bloom published "Space/Time Trade-offs in Hash Coding with Allowable Errors" in 1970. His example was a hyphenation program: suppose simple rules hyphenate 90% of English words correctly, and the other 10% need a dictionary that lives on disk. A small structure in memory that answers "definitely not in the dictionary" for most words avoids most of the disk reads, as long as you accept that it sometimes says "maybe" wrongly.

The problem it fixes

Before an expensive lookup (a disk read, a network request), you want to know cheaply whether it can possibly succeed. Storing the full set to check it costs too much memory.

How it works

An array of m bits, all 0, and k hash functions. Adding a value sets its k bits. Looking a value up: if any of its k bits is 0, it was never added; if all are 1, it was probably added (they may have been set by other values). No false negatives, a controlled rate of false positives, and no way to delete. The more bits per value, the fewer false positives.

Where it is used

  • Databases built on log-structured merge trees (LevelDB, RocksDB, Cassandra, Bigtable) keep a Bloom filter per file to skip the files that cannot contain a key.
  • Web caches and crawlers: "have we seen this URL?"
  • Networking: summarising what another machine holds without sending the whole list.
