Keep this
  • A stack is last in, first out: push and pop at the same end, both O(1).
  • A stack remembers where to come back to: function calls (the call stack), undo, the back button, nested brackets, depth-first search.
  • In Go, a slice is a stack: s = append(s, x) to push; x, s = s[len(s)-1], s[:len(s)-1] to pop. Check that it is not empty first.

The problem

A program calls a subroutine, which calls another, which calls another. Each must return to the right place in the one that called it, and the last one called is the first to return. The same shape appears when reading 3 × (4 + (5 − 1)): the innermost bracket opened last is closed first.

Where it comes from

In his 1946 design for the ACE computer, Alan Turing described two routines, BURY and UNBURY, to call subroutines and return from them using a stack of return addresses. In Munich, Friedrich Bauer and Klaus Samelson worked out in 1955 how a stack (their Keller, "cellar") lets a machine evaluate and translate formulas, and patented the method. It became the heart of compilers, and Bauer later received the IEEE Computer Pioneer Award for it. Every program you run today uses a stack for its function calls (lesson 1.3.1).

The idea

Only the top is visible. Pushing puts something on top; popping takes the top off. Nothing else is needed, which is why it is so fast and so common.

Why the browser needs two stacks

Back takes you to the last page you came from: that is a stack. Forward takes you to the last page you went back from: another stack. Visiting a new page clears the forward stack, because that future no longer exists. Undo and redo in an editor work the same way.
