  • BFS (breadth-first) explores level by level with a queue (1.2.4): it finds the shortest path counted in edges (hops).
  • DFS (depth-first) goes deep first with a stack or recursion (1.2.3, 1.3.1): reachability, cycles, ordering dependencies.
  • Both need a visited set, or a cycle makes them loop forever. Both are O(nodes + edges).

The problem

Which services break if the database goes down? What is the fewest number of hops from this router to that one? Does this set of dependencies contain a loop that makes deployment impossible? All three are walks through a graph, and a graph, unlike a tree, can lead you back where you have already been.

Where it comes from

Depth-first search is older than computers: in the 19th century the French engineer Charles Pierre Trémaux described a way out of any maze by marking the passages you have walked, published by Édouard Lucas in 1882. Breadth-first search was first written by Konrad Zuse in 1945 in his thesis on the Plankalkül language, which was rejected and stayed unpublished until 1972. It was reinvented in 1959 by Edward F. Moore to find the shortest path out of a maze, and in 1961 C. Y. Lee used it to route the wires on circuit boards.

The idea

Same loop, different container. Take a node from the container, visit it, put its unvisited neighbours in. With a queue, the nodes come out in order of distance: everything 1 hop away, then 2 hops. With a stack, the most recent node comes out first, so you dive down one branch before trying the next.

Where you run into them

Kubernetes garbage collection follows owner references to delete dependents; go mod graph and package managers walk dependency graphs; a network routing protocol computes shortest paths (with weights, which needs Dijkstra's algorithm, a BFS with a priority queue: 1.7.1). A crawler is a BFS over links.
