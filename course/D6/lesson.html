History

In 1962 the Atlas computer at Manchester introduced virtual memory: a small fast memory pretending to be a large one, pages moving in from a drum when needed. When memory is full, which page do you throw out? In 1966 László Bélády at IBM tested every replacement policy he could find. The best possible one (his MIN) needs to know the future; among the real ones, least recently used generally did best.

The problem it fixes

Fast memory is small. A cache must decide what to keep, and do it in O(1) on every access, or it costs more than it saves.

How it works

Bet that what was used recently will be used again soon. Two structures together: a doubly linked list keeps the entries in order of use (most recent at the front), and a hash table finds the list node of a key in O(1). On every access, move the node to the front; when full, drop the node at the back.

Where it is used

  • Operating systems: choosing which memory page to evict (approximations of LRU).
  • Processor caches use LRU-like policies inside each set.
  • Databases' buffer pools; Redis has an approximated LRU eviction mode.
  • Any memoisation with a size limit.
