History

Memory has been a row of numbered cells since the first stored-program computers of the late 1940s. An array is a run of consecutive cells, and finding element i is one multiplication and one addition on the address. The growable array came later; why "double when full" is cheap was put on firm ground by Robert Tarjan in 1985, who named amortized analysis: the rare expensive copy is paid for by the many cheap appends around it.

The problem it fixes

A fixed array must be sized in advance: too small and it overflows, too big and memory is wasted. Growing it by one cell at a time means copying everything at every append, O(n²) for n appends.

How it works

Keep spare room. When it runs out, allocate twice the size and copy once. Over n appends the copies add up to less than 2n moves: O(1) per append on average. A Go slice is exactly this: a pointer, a length and a capacity, and append grows the backing array when the capacity is reached. Two slices can share one backing array, which is fast and also the source of the classic aliasing bug (exercise 2).

Where it is used

  • Every Go slice, strings.Builder and bytes.Buffer.
  • The stack, the queue and the heap of this course are all built on one.
  • Any sequence read by index: pixels of an image, samples of a sound, rows of a table.
