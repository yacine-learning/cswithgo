History

The three orders were in use before computers, in how formulas are written. In the 1920s the Polish logician Jan Łukasiewicz wrote formulas with the operator first, × 3 + 4 1, which needs no brackets: a pre-order of the formula's tree, still called Polish notation. Its mirror, 3 4 1 + ×, is reverse Polish notation, a post-order; in 1957 the Australian Charles Hamblin showed that a machine can evaluate it with a stack. Our usual 3 × (4 + 1) is the in-order, and it needs brackets.

The problem it fixes

A tree has no single "next element". Every task on a tree (print it, evaluate it, copy it, delete it) needs a rule for the order in which the nodes are visited.

How it works

Visit a node and its subtrees, recursively; the only question is when you handle the node itself. Pre-order: before its children (copying a tree, creating folders top-down). In-order, for binary trees: between the left and the right subtree (a BST comes out sorted). Post-order: after its children (evaluating an expression, computing folder sizes, deleting a tree bottom-up).

Where it is used

  • Compilers: evaluating and generating code for expression trees (exercise 1).
  • File systems: mkdir -p works top-down, rm -r bottom-up (exercise 2).
  • An in-order walk of a BST lists its keys in sorted order.
  • Serialising a tree to JSON or XML is a pre-order walk.
