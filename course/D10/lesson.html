History

J. W. J. Williams, at Elliott Brothers in London (where Tony Hoare had just written quicksort, A7), invented the binary heap in 1963 to build a sorting method, heapsort, published in 1964. The same year Robert Floyd showed how to build a heap from n values in O(n). The heap outlived heapsort: today it is mostly a priority queue.

The problem it fixes

Many problems need "the smallest (or most urgent) item right now", over and over, while new items keep arriving. Sorting again after every insertion is O(n log n) each time; scanning for the minimum is O(n).

How it works

A complete binary tree stored in a slice, with no pointers: the children of index i are 2i+1 and 2i+2, its parent (i-1)/2. Rule: every parent is smaller than its children, so the minimum is always at index 0. Push: append at the end, then move up while smaller than the parent. Pop: move the last element to the root, then move it down, swapping with the smaller child. Both O(log n). Go's container/heap implements exactly this.

Where it is used

  • Go's runtime keeps its timers in a heap (4 children per node instead of 2): the next timer to fire is always on top.
  • Operating system schedulers: the most urgent task next.
  • Dijkstra's shortest paths (A13), Huffman coding (A17), merging k sorted files.
  • Top-k: the k largest of a stream, with a heap of size k (exercise 2).
