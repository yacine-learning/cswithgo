History

Arthur Kahn published the method in 1962 to order the tasks of large project networks: repeatedly take everything that has no unfinished prerequisite. In April 1976 at Bell Labs Stuart Feldman wrote make, which rebuilds a program from a graph of files and what each depends on, after a colleague lost a morning debugging a program that had simply not been recompiled.

The problem it fixes

Things that depend on each other must happen in an order where every dependency comes first: compile a package after what it imports, compute a spreadsheet cell after the cells it reads.

How it works

Count, for every node, how many dependencies it still waits for (its in-degree). Everything at 0 can go first. Each time a node is done, decrease the count of the nodes that depended on it; those reaching 0 can go next. If some nodes never reach 0, they are on a cycle and no order exists. Grouping the nodes that reach 0 together gives rounds that can run in parallel. O(nodes + edges).

Where it is used

  • Build systems: make, the Go toolchain compiling packages in dependency order (exercise 1).
  • Package managers installing dependencies before what needs them.
  • Spreadsheets recomputing cells; course prerequisites; the steps of any recipe.
