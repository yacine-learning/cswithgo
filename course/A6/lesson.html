History

Merge sort is credited to John von Neumann, who wrote it by hand in 1945 as one of the first programs for the EDVAC, a stored-program computer then being designed; Knuth's The Art of Computer Programming attributes it to him. Merging sorted tapes was how big files were sorted for decades, and it is still how data that does not fit in memory is sorted.

The problem it fixes

Simple sorts compare every pair, O(n²): a million items means a trillion comparisons.

How it works

Split the slice in two halves, sort each half (recursively), then merge the two sorted halves with two pointers (A4). There are log₂ n levels of halving and each level does n work: O(n log n), always. It needs a second array as big as the input. It is stable: equal elements keep their original order, which matters when you sort by one key after another.

Where it is used

  • Sorting data larger than memory: sort pieces that fit, write them out, merge them (external sort).
  • Stable sorts: Go's sort.Stable and slices.SortStableFunc keep equal elements in order.
  • Merging overlapping intervals once they are sorted (exercise 2).
