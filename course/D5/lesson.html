History

In January 1953 Hans Peter Luhn, at IBM, wrote an internal memo proposing to put records into "buckets" chosen by computing on the key, the records of one bucket chained together. Around the same time another IBM group (Amdahl, Boehme, Rochester and Samuel) used the same idea for the IBM 701 assembler's table of names. Arnold Dumey published it in 1956. Luhn also gave his name to the checksum on credit card numbers, and in 1958 wrote the first programs that indexed documents by counting their words (exercise 2).

The problem it fixes

Finding a key in a list means comparing it with every key, O(n). A sorted array with binary search is O(log n), but inserting into it shifts elements. We want find, insert and delete all in O(1).

How it works

A hash function turns the key into a number; that number, modulo the table size, picks a bucket. Two keys can land in the same bucket (a collision): keep them in a short list. When the table gets too full, double it and re-insert everything, as the dynamic array does (D1). Go randomises map iteration order on purpose, so no program can rely on it.

Where it is used

  • Every Go map (Swiss Tables since Go 1.24).
  • Compilers' symbol tables: from a name to its type and address.
  • Caches, sets, deduplication, counting.
  • Databases: hash indexes and hash joins.
